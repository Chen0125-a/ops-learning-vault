# 备份与同步规范

## 当前方案

1. 主库：`D:\笔记`，供 Obsidian 日常阅读和写作。
2. 版本历史与跨设备同步：私有 GitHub 仓库 `Chen0125-a/ops-learning-vault`。
3. 灾备：定期将整个 Obsidian 库备份到用户可控的加密离线介质或可信私有存储。

Git 是版本与恢复工具，不是唯一备份；Obsidian 同步也不能替代离线灾备。

## 提交前检查

1. 只提交白名单中的 Markdown、必要模板和经过审核的轻量附件。
2. 检查变更中没有密码、令牌、Cookie、API Key、私钥、认证文件、完整聊天记录或敏感终端输出。
3. 确认远程仓库为私有仓库。
4. 用精确文件路径暂存，不使用不加筛选的全量暂存。

## 建议的同步时机

- 完成一项重要协作决策后。
- 新增或修订已验证的长期协作记忆后。
- 每周至少一次检查本地状态和远程同步是否成功。

## 恢复演练

每月做一次五分钟演练：在不依赖旧聊天记录的情况下，让新任务读取 `CURRENT.md`、`COLLABORATION_MEMORY.md` 和 `DECISIONS.md`，确认它能说清当前主线、协作边界与安全规则。

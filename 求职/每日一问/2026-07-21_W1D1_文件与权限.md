## 一、摸底提问与批改（4 题）

### Q1. `ls -l` 第一列 `-rwxr-xr--` 拆解：第一个字符代表什么？后 9 个字符怎么分组？
- **我的回答**：第一个字符代表文件类型，后九个字符三个一组，分别代表拥有人、拥有组、其他人的权限
- **批改**：⚠️ 半对
- **解析**：框架对但细节缺失。文件类型字符需背全：`-` 普通文件 / `d` 目录 / `l` 软链接 / `c` 字符设备 / `b` 块设备 / `p` 管道 / `s` 套接字。三组权限对应 u（属主）/g（属组）/o（其他），数字换算 r=4 w=2 x=1，`rwxr-xr--` = 754。面试要求"逐字符读出来"，只说框架=背过没用过。
- **来源**：[JD高频·记忆层]

### Q2. 文件 644 属主 dev，root 执行 `chmod 000` 后，dev 还能读吗？root 还能读吗？为什么？
- **我的回答**：dev 不能读；root 不知道能不能读
- **批改**：❌ 错（核心考点）
- **解析**：dev 不能读 ✅；**root 能读、能写、能删**。原因：rwx 是 DAC（自主访问控制），内核检查权限时第一步看 uid 是否为 0（root），是则直接放行，不看 rwx。root 像物业万能钥匙，`chmod 000` 换锁挡不住万能钥匙。唯一能拦 root 的是 SELinux/AppArmor（MAC 强制访问控制）。**生产后果**：程序不能用 root 跑——被攻破=拿到万能钥匙，权限形同虚设。Nginx/MySQL 用专用低权用户运行的原因即此。
- **来源**：[JD高频·理解层] → 沉淀错题本

### Q3. 生产环境 `chmod -R 777 /var/www/html` 的危害（至少 2 条）+ 正确做法
- **我的回答**：① 陌生用户可能删除文件 ② 黑客入侵后恶意修改；正确做法：属主 rwx、属组 rwx、其他只读
- **批改**：⚠️ 半对（危害太笼统，正确做法写错）
- **解析**：危害应至少说出 4 条：① 任意用户可篡改文件（写 webshell）② **目录 777 最致命**——目录的 w=增删目录里的文件，任何用户能删掉整个目录 ③ x 给所有人=脚本可被替换为恶意脚本 ④ 违反最小权限原则，安全等保审计不通过 ⑤ 掩盖真正权限问题。正确权限：文件 644 / 目录 755 / 脚本 755 或 750 / 含密码配置 600。递归改权限要分文件和目录：`find /path -type d -exec chmod 755 {} \;` + `find /path -type f -exec chmod 644 {} \;`，一行 `chmod -R 777` 面试直接扣分。
- **来源**：[JD高频·应用层]

### Q4. chmod +x 后运行仍报 Permission denied，排查顺序（至少 3 步）
- **我的回答**：① `ll` 看文件权限 ② `whoami` 看当前用户
- **批改**：⚠️ 半对（只 2 步，缺 4 个关键点）
- **解析**：完整排查 6 步（从最常见到最罕见）：① `ls -l` 确认 x 真加上了 ② `whoami && id` 对照属主/属组 ③ **`ls -ld` 查父目录 x 权限**（父目录没 x 进不去，新人最常踩）④ `mount | grep` 查挂载点是否带 `noexec`（安全加固常见，全盘禁执行）⑤ `getenforce && ls -Z` 查 SELinux（MAC 能拦 root）⑥ 检查 shebang `#!/bin/bash` 解释器是否存在可执行。排错核心思维：从最常见到最罕见逐层排除，面试官要的是"有条理的排查链路"。
- **来源**：[排错场景层]

## 二、讲解要点（针对错点逐个讲透）

### 1. rwx 权限模型（配可视化图：Linux_文件权限模型）
- 10 字符 = 1 类型 + 3×3 权限（u/g/o）
- **对文件 vs 对目录的 rwx 差异**（最易混考点）：
  - r：文件=读内容；目录=ls 列出文件名
  - w：文件=改内容；目录=**增删目录里的文件**
  - x：文件=当程序执行；目录=**进入/穿越目录（cd）**，没 x 连 ls 内容都不行
- 数字权限：r=4 w=2 x=1，每组累加

### 2. root 绕过 DAC（今天核心考点）
- DAC 权限检查：uid=0 直接放行，不看 rwx
- MAC（SELinux/AppArmor）才能拦 root，CentOS 默认开 SELinux
- 生产不用 root 跑服务的原因

### 3. SELinux context（用户主动追问后补充讲解）
- context = SELinux 给文件/进程贴的"安全标签"，类比机场安检（DAC 是小区门禁）
- `ls -Z` 查看，4 段：用户:角色:**类型(_t)**:级别，99% 场景只看 type
- Nginx 进程 type 是 `httpd_t`，只能读 `httpd_sys_content_t` 类型文件——文件放 /root 下 type 是 `admin_home_t`，rwx 全对也 403
- 三条命令：`getenforce`（看模式）、`ls -Z`（看标签）、`restorecon -Rv`（恢复标准标签）
- 面试话术："先确认 DAC 没问题，再查 SELinux context type 是否匹配服务进程类型"

### 4. Nginx 403 Forbidden 排查（5 方向）
① 文件没 r 权限 ② 目录缺 x（⭐ 最常踩）③ 属主属组不对 ④ SELinux 拦截（CentOS 特有）⑤ nginx.conf 配置 deny
- 套路：**先读 `/var/log/nginx/error.log` 再猜原因**，日志会直接说 Permission denied 还是 forbidden by rule

### C1. 读出 `drwxr-xr--`：文件类型？三组权限？数字权限？
- **我的回答**：目录；拥有人读写执行、拥有组读和执行、其他人只读；754
- **批改**：✅ 全对
- **来源**：[记忆层]

### C2. 目录 `drwxr--r--`（744），普通用户能 ls 吗？能 cd 吗？为什么？
- **我的回答**：能 ls（有 r），不能 cd（没 x）
- **批改**：✅ 满分——今天讲解的核心难点答准了
- **来源**：[理解层·错题变体]

### C3. 一条命令把 /data 下所有目录设 755、所有文件设 644
- **我的回答**：`find /data -type -d -exec chmod 755 {} \;` / `find /data -type -f -exec chmod 644 {} \;`
- **批改**：⚠️ 命令错误（思路全对，语法多短横线）
- **解析**：`-type` 的值 `d`/`f` **不带横线**，正确：`find /data -type d -exec chmod 755 {} \;`。`-exec` 结尾必须是 ` \;`（空格+反斜杠+分号）。面试会让手写，细节要练。
- **来源**：[应用层] → 沉淀错题本

## 四、实操记录

### 实操 1（必做）：权限全流程实战

**要求**：建用户 dev1 → 建 testdir/hello.sh（带 shebang）→ 验证无 x 执行报错 → chmod u+x 后运行成功 → 改 000 验证 root 能 cat（绕过 DAC）→ 目录 744 测 ls/cd

**执行命令与真实输出**：
```bash
# 建用户+密码
echo redhat | passwd --stdin dev1    # all authentication tokens updated successfully.
su - dev1

# 建目录和脚本
mkdir testdir && touch testdir/hello.sh
vim testdir/hello.sh                 # #!/bin/bash + echo "hello linux"

# 无 x 执行 → 报错
./hello.sh    # -bash: ./hello.sh: Permission denied

# 加 x → 成功
chmod u+x hello.sh
ls -l         # -rwxrw-r-- 1 dev1 dev1 31 hello.sh
./hello.sh    # hello linux

# root 改 000，dev1 执行失败，root 能 cat（✅ 核心考点验证成功）
chmod 000 hello.sh
su - dev1; ./hello.sh   # Permission denied
# root 下：
cat hello.sh            # 正常显示内容 → root 绕过 DAC

# 目录改 744
chmod 744 ./
ll -d    # drwxr--r-- 2 dev1 dev1
```

**验证结论**：
- ✅ root 读 000 文件成功——DAC 绕过考点亲眼验证
- ✅ 家目录权限验证：dev2 初次 `cd /home/dev1` Permission denied（家目录 700）；`chmod 711` 后 dev2 能 cd（有 x）但 `ls` 报 Permission denied（没 r）——**711 "能进不能看" 现象验证成功**
- ⚠️ testdir（744）的 other 测试初次只覆盖了 owner（dev1 属主）。老师初次批改误判（没核对属主，错怪用户），被用户纠正——**正确做法：换 dev2（other 身份）测试**
- 💡 用户主动提问"为什么 bash hello.sh 能跑"——讲解：`./脚本` 靠 x 权限直接执行；`bash 脚本` 靠 r 权限读给解释器，不需 x

**dev2 测 testdir（744）补充验证（✅ 通过）**：
```bash
su - dev2
ls /home/dev1/testdir/
# 输出：
#   ls: cannot access '/home/dev1/testdir/hello.sh': Permission denied
#   hello.sh
cd /home/dev1/testdir/
# 输出：-bash: cd: /home/dev1/testdir/: Permission denied
```

**验证结论**：
- ✅ `cd testdir` 报 Permission denied——**744 other 没 x 进不去，核心考点亲眼验证成功**
- ⭐ `ls testdir` 出现"名字能列出但每个文件报 cannot access Permission denied"——经典现象：r 能读目录的文件名单（hello.sh 显示出来），但读每个文件的详细属性需要 x，没 x 所以每个文件跟一条报错。**这是"有 r 没 x"目录在 ls 下的典型表现**，面试给出这段输出能解释即加分

### 实操 2（选做）：find 批量修正 webroot 权限

**执行命令与真实输出**：
```bash
cd /tmp && mkdir webroot; cd webroot
mkdir aaa bbb; touch {1..3}.html abc.sh
chmod -R 777 webroot/
find -type d -exec chmod 755 {} \;    # ⚠️ 漏写路径
find -type f -exec chmod 644 {} \;    # ⚠️ 漏写路径
ls -l webroot/    # 文件 644 目录 755，但 abc.sh 也是 644
```

**验证结论**：⚠️ 初做两个问题，后经返工全部修正 ✅
1. **find 漏写路径（严重）**：`find -type d` 没写路径，默认从当前目录（/tmp）开始找，把整个 /tmp 权限全改了。生产环境在 / 下执行=重置全系统权限，删库跑路级。必须 `find /tmp/webroot -type d ...`
2. **abc.sh 被改成 644 丢执行权限**：脚本应单独处理

**返工修正后（✅ 通过）**：
```bash
find webroot/ -type d -exec chmod 755 {} \;              # 带路径 ✅
find webroot/ -type f -exec chmod 644 {} \;              # 带路径 ✅
find webroot/ -type f -name "*.sh" -exec chmod 755 {} \; # 脚本单独处理 ✅
ls -l webroot/
# -rw-r--r-- 1.html/2.html/3.html   ✅
# drwxr-xr-x aaa bbb                ✅
# -rwxr-xr-x abc.sh                 ✅ 执行权限恢复
```
> 套路：批量改权限前先想"有没有特殊文件类型要区别对待"——脚本、配置、密钥不能一刀切。

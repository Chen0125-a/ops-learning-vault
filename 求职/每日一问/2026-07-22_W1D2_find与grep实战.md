## 一、错题变体快速重测（A 组 3 题，W1D1 错题提前过）

### A1. 小李把密码配置文件 chmod 000，说"除了我谁都看不了"，对吗？
- **我的回答**：不对，root 仍能读取；chmod 改的是 DAC 只拦普通用户，拦 root 只有 SELinux
- **批改**：✅ 全对——W1D1 核心错题消化
- **补充新点**：000 连属主自己也读不了，但**属主可随时 chmod 改回**（chmod 查的是"是不是文件主人"）。结论链：000 防不住 root、属主本人、有 sudo 的人；生产保护密码文件靠 600 + 专用账户 + sudo 审计
- **来源**：[错题变体·理解层]

### A2. 删 /var/log/nginx 下 7 天前的 .log 文件（当前在 /root）
- **我的回答**：不知道（查 7 天前的参数不会、匹配 .log 不会）
- **批改**：❌ 不会——W1D1 find 错题原坑复现，find 参数骨架未建立
- **正解**：`find /var/log/nginx -type f -name "*.log" -mtime +7 -exec rm -f {} \;`，生产铁律：**先干跑看清单，确认后再加 -exec rm**
- **来源**：[错题变体·应用层]

### A3. root 上传 index.html 后 403，error.log 报 `open() failed (13: Permission denied)`，排查顺序
- **我的回答**：排除了文件不存在；先看文件权限和 context，再看父目录权限和 context
- **批改**：⚠️ 半对（两处硬伤）
- **解析**：① 日志解读答偏——`Permission denied` 排除的是**配置层 deny**（forbidden by rule 才是配置层；No such file 才是文件不存在）② 没写验证命令（题目硬性要求）
- **完整链路**：`ls -l` 文件权限属主 → `ps aux | grep nginx` 对照运行用户 → `ls -ld` 逐级父目录 x → `getenforce` + `ls -Z` SELinux（root 上传文件常带 admin_home_t，`restorecon -Rv` 修）
- **来源**：[错题变体·排错场景]

## 二、摸底诊断（B 组 4 题）——水位：全不会，切新课模式

### B1. grep 不分大小写找 error 带行号 / 只看不包含的行
- **我的回答**：`grep error -A -n`（第二问不知道）
- **批改**：❌ `-A` 是 After（显示匹配行后 N 行），不分大小写是 `-i`；反向是 `-v`
- **正解**：`grep -in "error" /var/log/messages`；`grep -v "error" ...`
- **来源**：[JD高频·记忆层]

### B2. `-mtime -7` / `7` / `+7` 含义
- **我的回答**：不知道
- **批改**：❌（核心新知识点，配时间轴图讲解）
- **正解**：`-7` = 7 天内（比 7 天新）；`7` = 恰好第 7 天；`+7` = 7 天以前（比 7 天老）。类比年龄：`-` = 以下，`+` = 以上
- **来源**：[JD高频·理解层]

### B3. / 分区 95%，找大于 500M 的文件前 10 个
- **我的回答**：不知道
- **批改**：❌
- **正解**：`find / -xdev -type f -size +500M -exec du -h {} \; 2>/dev/null | sort -rh | head -10`（`-xdev` 不跨文件系统避开 /proc；`2>/dev/null` 屏蔽权限报错）；生产套路：先 `df -h` 定位分区 → 再找大文件 → 删前 `lsof` 确认谁在用
- **来源**：[JD高频·应用层]

### B4. 24 小时内被传 webshell（.php 随机文件名），快速列嫌疑清单
- **我的回答**：`find /var/www/html/ -f *.php`
- **批改**：❌ 三处错：`-f` 非法（应 `-type f`）；`*.php` 裸奔（应 `-name "*.php"`）；**丢了核心考点 `-mtime -1`**
- **正解**：`find /var/www/html -type f -name "*.php" -mtime -1`；缩小范围：`-user nginx` 按属主筛 / `-newermt` 时间窗 / `grep -rl "eval\|system\|shell_exec"` 内容特征
- **生产意识**：找到 webshell 不能直接删（等于帮黑客擦痕迹）——先取证、查 access.log 找入口、堵漏洞、再清理
- **来源**：[排错场景层]

## 三、讲解要点

### 1. find 五要素模型（配图：find命令五要素拆解）
`find 路径 -type 类型 -name "名字" -mtime 时间 -exec 动作 {} \;`
- 路径必须显式写；`-type` 值 d/f/l 不带横线；通配符必须加引号；`{}` 占位 `\;` 收尾
- 生产铁律：删除类命令**先干跑看清单，核对后再动手**

### 2. mtime 时间轴（配图：find_mtime三种时间语义）
`-` = within 以内（新），`+` = beyond 超过（老），不带符号 = 恰好那天

### 3. grep 六大参数
`-i` 不分大小写 / `-n` 行号 / `-v` 反向 / `-c` 统计**行数**（非次数）/ `-r` 递归 / `-A -B -C` 上下文；`-l` 只列文件名
- `-c` 与 `wc -l` 区别：`-c` 可配合 `-r` 按文件分别统计
- 规范：选项前置、模式加引号

### 4. HTTP 状态码（用户主动坦白"不知道 500"）
403 拒绝 / 404 找不到 / 500 应用内部崩（看应用日志）/ 502 后端死了 / 503 过载 / 504 后端超时
口诀：**4xx 请求方的锅，5xx 服务器的锅**

## 四、巩固提问与批改（C 组 4 题）

### C1. 去掉 access.log 里 healthcheck 行；统计行数两个办法
- **我的回答**：`grep healthcheck -v access.log`；`grep healthcheck -vn`；`| wc -l`
- **批改**：⚠️ 主答案对（选项应前置、模式加引号）；`-vn` 概念混（-n 是行号不是统计）；统计只给出一个办法，缺 `grep -vc`

### C2. 清理 /tmp 下 30 天没动过的文件：甲 `-mtime -30` 乙 `-mtime +30` 哪个对
- **我的回答**：甲错（代表 30 天内），乙对
- **批改**：✅ 全对。生产后果：用甲会删掉正在活跃使用的临时文件，程序当场崩

### C3. 找 /etc 下最近 7 天改过的 .conf（"谁动了我的配置"）
- **我的回答**：`find /etc -type f -mtime -7 -name "*.conf"`
- **批改**：✅ 全对，五要素满分

### C4. /var/log 递归搜 OutOfMemory 带文件名行号；只列文件名换什么参数
- **我的回答**：`grep -rn OutOfMemory /var/log`；追问没答；主动坦白不知道 500 含义
- **批改**：⚠️ 主命令对；只列文件名是 `-l`；HTTP 状态码表已补讲

## 五、实操记录

### 实操 1（必做）：日志清理 + webshell 排查综合演练

**场景**：/tmp/ops 下 logs/（old1、old2=10天前，recent=3天前，today=今天）+ webroot/（正常 php=3天前，uploads/shell.php=24h 内）

**T1 初做 ❌ 严重翻车——删反了**：
```bash
find logs/ -type f -mtime -7 -name "*.log"
# 列出 recent.log today.log（7 天"内"的新文件）
find logs/ -type f -mtime -7 -name "*.log" -exec rm -rf {} \;
ls -l logs/   # 剩 old1.log old2.log —— 该删的留下，该留的删了
```
- **错在哪**：任务要求删"7 天**前**"应用 `-mtime +7`，写成 `-7`（7 天内），清理对象完全颠倒
- **深层问题**：干跑清单（recent/today 明明是新文件）与目标（删老文件）矛盾，没核对就直接 rm——dry-run 走了形式没走脑子
- **生产后果**：最近 7 天日志（排障最需要）全灭，10 天前垃圾还在，磁盘照样爆满且故障无日志可查——删库跑路标准剧本
- **连带**：删文件应用 `rm -f`，`rm -rf` 是核弹别成肌肉记忆

**T2 ✅ 满分**：`find webroot/ -type f -mtime -1 -name "*.php"` 精准命中 uploads/shell.php
**T3 ✅ 通过**：`grep eval -rl webroot/` 命中 shell.php（选项应前置）

**T4 初做 ⚠️ 连锁受害**：
- today.log 被 T1 误删后重建，但用 echo 重建导致 `\n` 是字面字符、全文 1 行（应用 printf）
- `grep -c` 输出 1，正确答案应为 2（`-c` 数**匹配行数**非次数：第 2 行 ERROR + 第 4 行 error = 2 行）
- ⭐ **用户主动发现矛盾并质疑**："T1 把 .log 都删了，T4 还怎么统计"——对输出保持怀疑的运维本能，本轮最大亮点

**T1 返工 ✅ 满分**：
```bash
find logs/ -type f -mtime +7 -name "*.log"
# 列出 old1.log old2.log ✅ 清单正确
find logs/ -type f -mtime +7 -name "*.log" -exec rm -rf {} \;
ls logs/   # recent.log today.log ✅
```

**T4 返工**：
```bash
grep -in error logs/today.log
# 2:10:01:23 ERROR connect to db failed
# 4:10:05:47 error disk almost full        ✅ 完美
grep -c error logs/today.log
# 1                                          ⚠️ 漏了 -i
```
- `grep -c error`（无 -i）只匹配小写第 4 行 = 1，命令与输出自洽
- 对照活教材：`grep -ic "error"` = 2（ERROR、error 都数）；`grep -c error` = 1（只数小写）

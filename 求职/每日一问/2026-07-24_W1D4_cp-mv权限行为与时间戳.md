## 一、错题重测（A 组 2 题，D1 到期二次变体）

### A1. [错题变体] chmod 000 挡 root 被领导驳回：a) 领导为什么对 b) 靠什么机制拦 root
- **我的回答**：chmod 拦普通用户，root 只能被 SELinux（context）拦
- **批改**：✅——DAC 本质答对；补充精确化：SELinux 拦的是"进程 domain 与文件 type 不匹配"
- **结算**：连续 2 次变体答对（07-22、07-24），**清零出本** ✅

### A2. [错题变体] 删 /data/logs 下 20 天前的 .log（先干跑后删除）
- **我的回答**：`find /data/logs -type f -mtime +20` / `... -exec rm -rf {} \;`
- **批改**：⚠️ 半对——`+20` 方向 ✅、路径 ✅、`-type f` ✅，**但漏了 `-name "*.log"`**（会删掉 20 天前的所有文件）；`-rf` 中 `-r` 多余
- **正解**：`find /data/logs -type f -name "*.log" -mtime +20 -exec rm -f {} \;`
- **结算**：1对1错 → 2026-07-27 重测

## 二、T3 路径疑案破解（W1D3 遗留）

- **证据**：`ls -li` 显示 /ops/backup/ 下无 hard 文件；/ops/conf/ 下 app.conf(inode 3053275, 10 字节) 与 app.conf.hard(inode **3053274**, 7 字节)
- **结论**：用户贴的 `ln ... /ops/backup/app.conf.hard` 是**贴命令时笔误**，实际建在 conf/ 下，操作本身全对

## 三、SSH 免密配置 + IP 冲突排错（40 分钟实战，今日最佳教材）

### 排错全程（现象 → 假设 → 验证 → 结论）
1. paramiko 连 .200 失败 → 探测 22 端口 **Connection refused**（关键知识点：**refused=没人监听；timeout=防火墙 DROP/路由不通**）
2. 用户启动 sshd（`systemctl enable --now sshd`）后仍 refused
3. ipconfig 显示宿主 VMnet8 = 192.168.100.200 → 一度误判".200 是宿主网卡"（老师的错误：没验 MAC 就下结论，违反自己定的批改铁律，已当众认错）
4. **`arp -a` 破案**：`.200 → 00-0c-29-c7-c6-c1`（`00:0C:29` = VMware 虚拟机网卡 OUI）→ .200 确实是 VM
5. **完整真相**：VM 和宿主 VMnet8 **都曾配成 .200（IP 冲突）**，宿主"本机优先"应答导致 ping 0ms + refused；用户把宿主 VMnet8 改为 .253 后冲突解除，秒通
6. banner `OpenSSH_8.0` = CentOS/Rocky **8 系**默认版本（宿主机系统：CentOS Linux 8）

### 排错清单沉淀（"ping 通但服务连不上"）
ping 通 → 端口探测（refused/timeout 分流）→ 服务监听（ss -tlnp）→ 防火墙 → **IP 冲突（arp -a 验 MAC OUI）**

### 免密部署（AI 完成）
- 宿主机 ed25519 密钥对 → paramiko 密码连一次部署公钥 → `.ssh` 700 / `authorized_keys` 600
- 知识点：`StrictModes yes` 下权限过宽（如 644）sshd 会**拒绝使用** authorized_keys——"免密死活不生效但密码能登"的经典故障
- **安全约定**：密码仅用于一次性部署，不落盘、不归档；今后只发 IP+用户名

## 五、新课讲解要点

### 1. cp = 投胎转世（读源 → 全新文件）
- 新文件：新 inode / 权限=**源权限抠 umask**（⚠️ 与新建区分：touch/mkdir 是**满配 666/777 抠 umask**）/ 属主=执行者 / 时间戳=当前
- 备份标准：`cp -p`（保权限属主时间戳）、**`cp -a`（归档模式，生产备份标准命令）**

### 2. mv = 同分区改户口，跨分区搬家公司
- 同分区 = rename，**只改目录项**（目录项在**目录**里：目录是存"文件名→inode"清单的特殊文件，**不在 inode 里**）；inode/数据/权限/时间戳全不变，10G 也秒完
- 彩蛋：同分区 mv 后 inode 不变但 **ctime 刷新**（目录项变了）
- 跨分区 = cp + rm（inode 必变），默认保留属性，先复制完再删源，中断不丢数据
- 插曲（用户实测抓到的）：`mv` 覆盖有提示是因为 `/root/.bashrc` 里 `alias mv='mv -i'`（还有 rm/cp 同款）；**alias 只在交互 shell 生效**，脚本/cron 里是原生命令——生产脚本用 `\rm` 或 `/bin/rm` 绕过

### 3. 时间戳三兄弟（stat 查看）
| 时间戳 | 何时变 |
|---|---|
| mtime | **内容**被改（echo >>） |
| ctime | **元数据**变更（chmod/改名/链接数，**改内容连带变**） |
| atime | 被读取（relatime 优化：不每次都更新） |
- **取证核心**：`touch -d` 能伪造 mtime，**ctime 无法伪造**（任何操作都刷成真实当前时间）→ 排查篡改用 `find /etc -ctime -N`
- 口诀：**mtime 会演戏，ctime 不说谎**

## 二、讲解要点

### 1. umask（按新课讲透）
- **是什么**：新建文件/目录的默认权限"减法滤镜"。底子：**文件 666（默认不该可执行）/ 目录 777**
- **怎么算**：按位掩码抠掉 umask 位。root 022：文件 666→644，目录 777→755
- **⚠️ 经典坑**：不是算术减法！umask 023 时文件 = 666 掩掉 `--- -w- -wx` = **644**；算术减 666−023=643 明显荒谬（其他人凭空多 x）
- **三个常用值**：022（root 默认，644/755）、002（普通用户，664/775）、077（高安全，600/700）
- **生效时机（T2 考点）**：umask 是**进程属性**，只在文件**创建那一刻**生效（"出厂设置"），已存在的文件不受影响，要改只能 chmod
- **永久生效位置（C2 考点）**：应用启动脚本开头 > 运行用户 `~/.bashrc` > 全局 `/etc/profile`（影响面大，生产慎用）

### 2. inode 与软硬链接（配图：inode与软硬链接原理图）
- **inode**：文件的身份证+档案卡（权限/属主/大小/时间/数据块位置），**文件名不存在 inode 里**，文件名只是目录里指向 inode 的"标签"
- **硬链接**：同一 inode 再贴一张标签，计数+1；两标签**地位完全平等**，删哪个都一样，计数归 0 数据才销毁
- **软链接**：独立小文件（自己的 inode），内容是一行**路径字符串**；源文件名没了→断链
- **区别表**：inode 号（同/不同）、删源文件（没事/断链）、跨文件系统（❌/✅）、链目录（❌/✅）、链接数（+1/不变）、命令（`ln` / `ln -s`）
- **必须用软链的两场景**：跨分区、链目录（Nginx 版本切换 `ln -s` 换指向即 W4 伏笔）
- **ln 套娃坑（C4 考点）**：`ln -s 源 已存在的目录软链` 会**跟随进目录**把链接建到里面（套娃），正解 `ln -sfn`——`-n` 把链接名当普通文件不跟随，`-f` 强制覆盖，一步原子替换
- 彩蛋：`ls -ld /ops` 链接数 6 = 2 + 子目录数（每个子目录的 `..` 指回来）

### 3. 软链接路径选择：绝对 vs 相对（00:03 举一反三补讲）
- **硬链接没有"路径"问题**：建的是"文件名 → inode"直接关联，inode 直达数据，绝对/相对随便写
- **坑 1**：相对路径软链以**链接所在目录**为基准解析，不是以敲命令时的 cwd 为基准。`ln -s ../conf/app.conf /ops/backup/app.conf.soft` 中的 `../conf` 相对于 /ops/backup 解析
- **坑 2**：跨目录引用（如 /etc 链到 /opt 的配置）用相对路径，换位置访问或链接移动即断链——**跨目录引用一律绝对路径（生产纪律）**
- **举一反三 ①（相对路径反而正确的场景）**：**同一目录树内部互链**用相对路径（如 nginx `sites-enabled/xxx -> ../sites-available/xxx`）——整树打包迁移到别的机器/路径，树内相对软链依然有效，绝对路径全断。"绝对 vs 相对"不是对错，是看要不要"整树可搬"
- **举一反三 ②**：`ln -s` 建软链时**源文件不存在也能建成**（shell 不检查），建出来就是断链——部署脚本路径打错一个字母 = 定时断链，用 `find -xtype l` 定期排查

## 三、费曼检验（3 题复述）

1. **umask 022 为什么是 644**：底子 666 rw-rw-rw 去掉 --- -w- -w- = rw-r--r-- ✅（用词"减去"有隐患，C1 埋坑题验证通过）
2. **删源文件硬链接为什么没事**：inode 指向磁盘同一位置共用数据，计数 2−1 还剩 1 ✅（补讲"两标签地位平等，删哪个都一样"）
3. **只能用软链的场景**：跨文件系统/分区、链接目录 ✅

## 五、实操记录（P1 子任务：/ops 运维实验基地）

### T1 ✅：一条命令建目录树 + 默认权限解释
```bash
mkdir -p /ops/{scripts,logs,conf,backup}
ls -ld /ops/   # drwxr-xr-x 6 root root
```
解释正确：目录底子 777 去掉 022 = 755。（彩蛋：链接数 6 = 2 + 4 个子目录）

### T2 ✅（疑问已解答）：umask 027→tmp(750) / 改回 022→tmp2(755) / tmp 不变
```bash
umask 027; mkdir tmp   # drwxr-x--- ✅ 预期正确
umask 022; mkdir tmp2  # drwxr-xr-x ✅
ls -ld tmp/            # drwxr-x--- 不变 ✅
```
- 问"为什么 tmp 不变"答不出 → 讲解：**umask 是进程属性，只在创建那一刻生效（出厂设置）**，已存在文件不受影响，要改只能 chmod → 并入 C2 错题

### T3 ✅（一处路径待澄清）：软硬链接创建 + inode 对比
```bash
ln -s /ops/conf/app.conf /ops/backup/app.conf.soft
ln /ops/conf/app.conf /ops/backup/app.conf.hard
ls -i conf/app.conf conf/app.conf.hard backup/app.conf.soft
# 68138265 backup/app.conf.soft   3053274 conf/app.conf   3053274 conf/app.conf.hard
```
- ✅ inode 验证教科书级：app.conf 与 hard **同 inode（3053274）**，soft 独立（68138265）；`ls -l` 链接数 2 ✅
- ⚠️ 小瑕疵：第一次 `echo 123123 conf/app.conf` 漏 `>` 重定向（自己发现并纠正）
- ❓ **待澄清**：贴的 ln 命令硬链接目标是 `/ops/backup/app.conf.hard`，但 `ls -i` 查的 `conf/app.conf.hard` 却存在且 inode 相同——两个路径对不上，明早贴 `ls -li /ops/conf/ /ops/backup/` 核实到底建在哪（运维必须对"自己执行了什么"心里有数）

### T4 ✅ 满分（今日最佳对照实验）
```bash
cat conf/app.conf.hard backup/app.conf.soft
# 123123                                            ← 硬链接：计数 2→1，数据还在 ✅
# cat: backup/app.conf.soft: No such file or directory  ← 软链接：断链 ✅
find /ops/ -xtype l -exec ls -ld {} \;              ← 断链一条命令命中 ✅
```

### T5 ✅：`ln -sfn` 重指向 + readlink 验证（ls -ld 等效）
```bash
echo version=2 > conf/app.conf
ln -sfn /ops/conf/app.conf /ops/backup/app.conf.soft
ls -ld backup/app.conf.soft   # -> /ops/conf/app.conf ✅
```

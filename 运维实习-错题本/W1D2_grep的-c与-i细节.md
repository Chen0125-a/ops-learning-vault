# 错题：grep 的 -c 与 -i 细节

## 错误 1：统计行数只记住 `wc -l`，忘了 `grep -c`
```bash
grep -vc "healthcheck" access.log          # 办法一：grep 自带 -c
grep -v "healthcheck" access.log | wc -l   # 办法二：wc -l
```
区别：`-c` 配合 `-r` 可**按文件分别统计**（`grep -rc "error" /var/log` 列出每个文件各几次），`wc -l` 只能数总数。

## 错误 2：`-c` 的语义记错——数的是"匹配行数"，不是"出现次数"
一行里 error 出现 100 次，`-c` 也只数 1 行。
实例（5 行日志：第 2 行 ERROR、第 4 行 error）：
- `grep -ic "error" file` → **2**（大小写都算上，2 行匹配）
- `grep -c "error" file` → **1**（区分大小写，只有第 4 行小写匹配）

## 错误 3：漏 `-i` 导致统计口径变小
题目要求"不分大小写"，实操写成 `grep -c error`（没 -i），输出 1 而非 2。
命令与输出自洽 ≠ 满足题意——**先想清楚统计口径，再决定加不加 -i**。

## 关联易混参数
- `-n` 是显示行号，**不是**统计行数（当天曾写出 `grep -vn` 想数行数）
- `-l` 只列文件名（配合 -r 用）；`-L` 只列**不包含**的文件名

## 错误 4（W1D3 C5 变体抽查新增）：漏文件名
`grep -ic error`（没给文件）——回车后 grep 挂住等标准输入，统计不了任何日志。
正解：`grep -ic "error" /var/log/messages`（文件路径必须有，模式加引号是规范）。
手写命令漏文件 = 跑不起来，面试白板题这种丢分最冤。

# 错题：ln -sfn 版本切换防套娃

## 事故场景
`/usr/local/nginx` 是指向 `/opt/nginx-1.24` 的软链接，升级到 1.26 时执行：
```bash
ln -s /opt/nginx-1.26 /usr/local/nginx     # ❌ 错误命令
```
**结果**：`/usr/local/nginx` 还指向 1.24（没切换），且旧目录里多了个 `nginx-1.26` 链接（套娃）。

## 原理
链接名**已存在且是指向目录的软链接**时，`ln` 默认**跟随**（dereference）它，把新链接建到那个目录**里面**。

## 正解（面试标准答案）
```bash
ln -sfn /opt/nginx-1.26 /usr/local/nginx
readlink -f /usr/local/nginx    # 验证指向
```
- `-f`（force）：链接名已存在先删再建
- `-n`（no-dereference）：把已存在的链接名**当普通文件、不跟随进目录**——防套娃关键
- "先 rm 再 ln -s"两步也可行，但中间有瞬断窗口；`-sfn` 一步原子替换

## 生产后果
以为升级完成实际还跑旧版本——漏洞"修了但没修"，安全扫描/故障复盘时才暴露版本漂移。

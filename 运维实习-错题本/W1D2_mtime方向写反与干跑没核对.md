# 错题：mtime 方向写反 + 干跑清单没核对（删库级事故）

## 事故现场
任务：删 logs/ 下 **7 天前**的 .log 文件。
**我执行的**：`find logs/ -type f -mtime -7 -name "*.log" -exec rm -rf {} \;` ❌
**结果**：删掉了 recent.log、today.log（7 天内的新文件），留下了 old1/old2（10 天前的老文件）——**清理对象完全颠倒**。

## 错误 1：`-mtime -7` 和 `+7` 写反
- `-mtime -7` = 7 天**内**（比 7 天新）
- `-mtime +7` = 7 天**以前**（比 7 天老）✅ 本题该用这个
- 记法：年龄类比——`-` = 以下（新），`+` = 以上（老）
- **讽刺的是**：当天 C2 口头题我答对了（+30 才是 30 天前），一小时后实操就写反。**口头懂 ≠ 手上会**，方向性参数必须上机验证。

## 错误 2：干跑看了清单但没核对（更致命）
干跑输出 `recent.log today.log` 与目标"删老文件"明显矛盾，没发现就直接 `-exec rm`。
**dry-run 的意义不是走形式，是逼自己问一句：列出来的是不是我想删的？**

## 生产后果
生产日志清理跑反方向：最近 7 天日志（排障最需要）全灭，老垃圾还占着磁盘——磁盘照样爆满，出故障没日志可查。双杀。

## 正确姿势
```bash
find logs/ -type f -mtime +7 -name "*.log"      # 1. 干跑
# 核对：列出来的是不是老文件？                      2. 核对！
find logs/ -type f -mtime +7 -name "*.log" -exec rm -f {} \;   # 3. 才动手
ls -l logs/                                      # 4. 验证
```

## 附加小错
删文件用 `rm -f` 即可，`rm -rf` 是删目录的核弹命令，别让它成为肌肉记忆。
